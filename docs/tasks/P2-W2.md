# Task P2-W2: SQLite store for scans, nodes and unmeasured paths

**Role:** implementer · **Branch:** `task/P2-W2` · **Phase:** 2 · **Runs in parallel with P2-W1** (scanner). Never touch their files.

## Goal
Implement `internal/store`: macdoc's local state database. It persists scans and their kept nodes so read-only commands can reuse recent results, and so `trend` can show growth over time later.

## Requirements
1. **Open:**
   - Create parent directories with mode 0700 and the db file with mode 0600. Check the mode even if the file already exists, and tighten it if it's looser.
   - Pragmas: `journal_mode=WAL`, `busy_timeout=5000`, `foreign_keys=ON`, `synchronous=NORMAL`.
   - Apply migrations in order, tracked in a `schema_migrations(version INTEGER PRIMARY KEY, applied_at)` table, inside transactions. Re-opening is idempotent. A database with a **newer** schema than the code knows is an error (don't downgrade).
2. **Schema (v1)** with foreign keys and `ON DELETE CASCADE`:
   - `scans(id TEXT PK, root, started_at, finished_at NULL, status, total_bytes, total_files, unmeasured_count, macdoc_version)`
   - `nodes(scan_id FK, path, path_fold, kind, bytes, files, mtime_max, depth, PRIMARY KEY(scan_id, path_fold))`
   - `unmeasured(scan_id FK, path, reason)`
   - Indexes: `nodes(scan_id, bytes DESC)` and `scans(started_at)`.
   - Times are stored as UTC RFC3339Nano text, or unix nanos; pick one and be consistent.
3. **path_fold:** NFC, then `strings.ToLower`. Use it for prefix queries and `History`. Prefix matching is component-wise: `path_fold = p OR path_fold LIKE p || '/%' ESCAPE '\'`, with `%`, `_` and `\` in `p` escaped. A prefix of `/` matches everything.
4. **IDs:** `S-` plus 8 chars of crypto-random base32 (no padding, uppercase). Retry on collision.
5. **AddNodes:** batched inserts inside one transaction using a prepared statement. A duplicate path in the same scan updates the row (upsert). It's an error unless the scan is `running`.
6. **FinishScan:** set `unmeasured_count` from the stored rows. Only `complete` or `incomplete` are accepted.
7. **Nodes:**
   - Ordering is Bytes descending, then Path ascending.
   - `MaxDepth` is relative to the prefix's own depth. Store depth per node and compute the prefix depth from its components; `/` has depth 0.
   - Respect `Limit`.
8. **History:** an exact `path_fold` match, complete scans only, oldest first, at most `limit` rows (0 means unlimited; take the **newest** `limit` and return them oldest first).
9. **PruneScans:** as documented. Rows are removed through the cascade. Then run `PRAGMA wal_checkpoint(TRUNCATE)` (no VACUUM).
10. **Concurrency:** methods must be safe from multiple goroutines. `database/sql` pooling is fine; set `SetMaxOpenConns` sensibly for SQLite and WAL.
11. **No file deletion and no exec.** forbidcheck applies. Removing database rows is fine.

## Tests (all under `t.TempDir()`)
- Open creates directories and file with the right modes, tightens a loose existing mode, re-opens idempotently, and rejects a future schema version (insert a fake higher migration row).
- The full lifecycle: BeginScan, AddNodes (in several batches, including an upsert), AddUnmeasured, FinishScan, then Scan / LatestScan / Nodes / Unmeasured.
- LatestScan by status, and ErrNoScan on an empty database.
- Nodes queries:
  - prefix component-wise (`/Users/a` doesn't match `/Users/ab`)
  - case-insensitive
  - NFD input against an NFC-stored path
  - prefix containing `%` and `_`
  - MinBytes, MaxDepth and Limit
  - ordering and tie-break
- AddNodes or FinishScan on a finished scan returns an error.
- History across 3 scans, including an incomplete one, which is excluded. Limit returns the newest N, oldest first.
- PruneScans keeps the newest N complete scans, the cascade removes their rows, and running scans are untouched.
- Concurrency: parallel readers while a writer adds batches, run under `-race`.
- **Benchmark** `BenchmarkAddNodes`: 50k nodes in batches of 1k. Target is under 1 s on this Mac; report the result.
- Coverage ≥ 90%.
