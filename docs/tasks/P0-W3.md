## Decisions (tech lead)

**D1 (RT-01): parents of named protected roots are protected.**
- A path is protected if it is a **strict ancestor** of any home-relative protected root, any `extraProtected` root (both lexical and resolved forms), or `~/Library/Containers` (lexical and resolved).
- Report it as `"contains protected path <root>"`.
- This doesn't apply to system roots; their parents are already covered by `/` and the home-ancestor rules.

**D2 (RT-02): reject trailing `/` and `/.`.**
- `Canonicalize` rejects any input other than `/` that ends in `/` or whose last raw component is `.`.
- Return `*Violation{RuleInvalid, "trailing slash or /."}`.
- Inner `.` components are still cleaned.

**D3 (RT-03): SQLite sidecars.**
- Also protect final components ending in `<suffix>-wal`, `<suffix>-shm` and `<suffix>-journal` for each of `.sqlite`, `.sqlite3` and `.db`.

**D4 (RT-04, A2): `.env*` files.**
- Protect any final component whose folded form starts with `.env`. This covers `.env`, `.envrc`, `.env-local`, `.env_prod`, `.env~` and so on.

**D5 (RT-05): containers.**
- The `com.apple.*` container rule compares against both the lexical and the resolved (`resolveFull`) `~/Library/Containers`.

**D6 (RT-06, A7): no cleanup target outside home.**
- `CheckTarget` returns `*Violation{RuleOutsideHome}` for any canonical path that isn't within the policy's home.
- Order: canonicalize, protected, outside-home, depth, allow.
- Update the `CheckTarget` doc comment: add a bullet saying "it is within $HOME (RuleOutsideHome); every macdoc target outside home is acted on only through native tool commands, never by path". Also update the `RuleOutsideHome` constant comment, since it's no longer "reserved".
- Also add `/.vol`, `/.file`, `/Network`, `/net` and `/home` to the system roots (defense in depth for `IsProtected`).
- Existing tests that expected `RuleNotAllowed` (or acceptance) for targets outside home must now expect `RuleOutsideHome`. List each one.

**D7 (RT-07): home location.**
- `NewPolicy` rejects a resolved home that is within any system root **unless** it's within `/private/var/folders` (temp dirs) or `/Volumes` (external-disk homes).
- Update the `NewPolicy` doc comment.
- Keep the containment exception logic working for those two cases.

**D8 (RT-08): sandbox input.**
- `sandbox.Check(path)` runs `safety.Canonicalize(path)`. It refuses on error, or if the canonical result isn't `samePath` with the input.
- Update its doc comment: "path must be canonical; non-canonical input is refused".

**D9 (RT-09): sandbox location.**
- Add `safety.SystemRoots() []string`, returning a **copy** of the system roots list.
- `sandbox.Root()` rejects a root that equals or contains any system root. It also rejects a root that is within a system root, unless the root is within `/private/var/folders` or `/private/tmp` (temp dirs).
- Update the doc comment.

**D10 (A1): set-but-empty fails closed.**
- `Root()` uses `os.LookupEnv`. If the variable is **set but empty** (or only whitespace), return `"", true, error`, so `Check` fails closed.
- Unset means inactive.
- Update the doc comment and the P0-R1 test `TestRedteamEmptyDisables` (it documents the old behavior). This is a deliberate override; report it.

**A5: `IsProtected` doc comment.** State loudly that the input must be canonical (from `Canonicalize`) and that non-canonical input can miss symlinked parents.
