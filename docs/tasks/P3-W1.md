## Hard rules for detectors
- **Read-only.** Use scan data (`env.Nodes`), file reads (`os.ReadFile`, `os.ReadDir`, `os.Lstat`), and `env.Runner` for listing commands. No writes and no exec outside `env.Runner`. forbidcheck applies.
- **Never run a tool with side effects to discover things.** On this Mac, querying pnpm or yarn made Corepack download binaries.
- If a tool is missing (`ToolInstalled` false, or the Runner errors with "not found" / "unable to find utility"), return `nil, nil`. Missing tools aren't errors.
- `NativeArg` must come verbatim from the tool's own listing or registry (`simctl` JSON identifiers, AVD names from `~/.android/avd/*.ini`). Validate it: reject anything with whitespace, `/` or shell characters.
- Quarantine targets must lie under home and match the recipe's `allow` patterns. The classifier (P3-W3) calls `safety.CheckTarget` on every one, so write patterns that pass the lint (min depth 2, no `**` at depth < 2).
- Sizes come from the scan (`model.SourceMeasured`) or from the tool (`SourceTool`). If neither is available, use `SourceUnknown` with a reason. Never use 0 to mean unknown.

**Android** (`android.yaml`). The SDK root is `$ANDROID_HOME`, else `$ANDROID_SDK_ROOT`, else `~/Library/Android/sdk`. **Reading env vars is fine. SDK package removal uses quarantine, not sdkmanager:** on this Mac, `sdkmanager` is Homebrew's and points at a different SDK root, and our argv can't template `--sdk_root`. Removing a package directory is exactly what an uninstall does, and quarantine keeps it restorable.

| ID | Detector | Method / risk | Notes |
|---|---|---|---|
| `gradle.caches` | `path` `~/.gradle/caches` | quarantine, SAFE | Preconditions `gradle_daemons_stopped` and `app_not_running:Android Studio` |
| `gradle.wrapper_dists_old` | new `gradle_wrapper_old` | quarantine, SAFE | Children of `~/.gradle/wrapper/dists` except the newest version. Note in `explain` that the Phase 4 project scan will refine this. |
| `android.avd` | new `android_avds` | native `avdmanager delete avd -n {id}`, CAUTION, stale_days 60 | Names from `~/.android/avd/*.ini`. Size from scan `~/.android/avd/<name>.avd` (`keep_children_of ~/.android/avd`). Precondition `emulator_not_running`. |
| `android.avd_snapshots` | new `android_avd_snapshots` | quarantine, SAFE | `~/.android/avd/*.avd/snapshots`. Precondition `emulator_not_running`. |

Allow patterns must be specific, for example `~/Library/Developer/Xcode/DerivedData/*` or `~/Library/Android/sdk/system-images/*/*/*`. For non-default SDK roots under home, detectors still emit targets. If such a target doesn't match the allow patterns, the classifier drops it with a warning. That's acceptable; mention it in the report.

## Tests (per recipe, per `docs/RECIPE_CATALOG.md` §3, adapted)
1. **Positive:** a synthetic `fakeNodes` and/or `fstree` home and/or `FakeRunner` JSON gives the expected findings (target, bytes, source, NativeArg, title).
2. **Look-alike negative:** something similar that must **not** be emitted, e.g. the newest DeviceSupport version, an NDK that is the only one, `AndroidStudio2024.1` when it's the newest, a system image referenced by an AVD, `DerivedData.bak`.
3. **Tool missing or unavailable:** `simctl_unavailable.txt` (real), `pod` not installed, and no SDK make the detector return `nil, nil`.

Also:
- Use `simctl` JSON fixtures that you **write** (`w1_simctl_runtime_list.json`, `w1_simctl_devices.json`), modeled on real `xcrun simctl … -j` output. Document the shape you assumed.
- Add a test that `Load()` succeeds with your YAML, and that every recipe ID you added is present.
- Coverage of your `detect_*.go` files ≥ 90%.
