## Assumed tool output shapes

**`xcrun simctl list -j devices`** (`testdata/w1_simctl_devices.json`): `{"devices": {"<runtime id>": [device…]}}`, where the key is e.g. `com.apple.CoreSimulator.SimRuntime.iOS-17-2`. The fields I use from each device are `udid`, `name`, `state` (`Shutdown`/`Booted`), `isAvailable` (bool) and `dataPathSize` (int, optional). Other real fields (`dataPath`, `logPath`, `availabilityError`, `deviceTypeIdentifier`, `lastBootedAt`) are present in the fixture and ignored.

**`xcrun simctl runtime list -j`** (`testdata/w1_simctl_runtime_list.json`): a top-level object keyed by runtime identifier (UUID). The fields I use from each value are `identifier` (must equal the key), `version` (`"17.2"`), `runtimeIdentifier` (the platform comes from it), `path`, `sizeBytes` (optional), `deletable` (bool) and `lastUsedAt` (RFC 3339, optional). Also present but ignored: `build`, `kind`, `mountPath`, `platformIdentifier`, `runtimeBundlePath`, `signatureState`, `state`.

**`xcrun --find simctl`**: exits 0 with the path when simctl is available. With the Command Line Tools only, it exits non-zero with the real `simctl_unavailable.txt` message.

**AVD registry:**
- `<avd home>/<name>.ini` has `path=<abs .avd dir>`.
- `<name>.avd/config.ini` has `image.sysdir.1=system-images/<api>/<tag>/<abi>/` (relative to the SDK root; absolute paths are handled too) and an optional `avd.ini.displayname`.
- The avd home is `$ANDROID_AVD_HOME`, else `$ANDROID_EMULATOR_HOME/avd`, else `~/.android/avd`.

## Deviations

1. **File name `detect_android.go` became `detect_androidsdk.go`, and the test is `detect_androidsdk_test.go`.** Go treats `*_android.go` as a `GOOS=android` build constraint, so the brief's file name never compiles on macOS. The catalog failed with "unknown detector" until I renamed it.
2. **`cocoapods.cache` uses a new `cocoapods_cache` detector instead of `path`.** The brief says "only when `pod` is installed", and the generic `path` detector can't check that. The new detector is `path` gated on `ToolInstalled("pod")`. I domain-prefixed all new detector names to avoid a duplicate-`Register` panic with P3-W2.
3. **`xcode.sim_runtimes_orphaned` also reports `/Library/Developer/CoreSimulator/Images`.** It's the same class of leftover (runtime disk images). The brief named only the AssetsV2 and dyld cache locations. It's advise-only either way.
4. **`xcode.simulators_unavailable` emits one aggregate finding with `Target ""`.** The single native command removes all of them, so per-device findings would run it N times. The size sums scan nodes, falling back to `dataPathSize`:
   - all from the scan: measured
   - some from simctl's `dataPathSize`: tool
   - some unmeasured: estimated, with a "lower bound" reason
   - none measured: unknown

   The device names are in `Note`.
5. **`xcode.sim_runtimes` skips runtimes with `deletable: false`, and a runtime whose `identifier` doesn't equal its listing key.** It still emits the newest runtime per platform, with a Note that Xcode needs it. `Target` is the runtime's own `path`, outside home, for display only.
6. **I added `simulator_not_running` to `xcode.sim_runtimes`, from catalog §2.** The brief's table gave it no precondition. I also added `emulator_not_running` to `android.system_images_unused`, next to `app_not_running:Android Studio`.
7. **Snapshot folders the scan didn't keep are skipped.** That means under the 100 MB keep threshold, usually empty. Other on-disk targets that aren't in the scan are emitted with `SourceUnknown` and a reason: SDK system images and old build-tools/NDK.
8. **Detectors with `stale_days` filter on staleness themselves** (`simctl_idle_devices`, `android_avds`), as the brief describes for idle devices and as P3-W2 does for `node_modules`. The generic `children` detector (`xcode.derived_data`, stale_days 30) does **not** filter. See question 1.
9. **The AVD home honours `$ANDROID_AVD_HOME` and `$ANDROID_EMULATOR_HOME`.** Otherwise images used by AVDs stored elsewhere would look unused.
10. **Targets under a non-default SDK root inside home are dropped.** They're still emitted, but the allow patterns only cover `~/Library/Android/sdk/...`, so the classifier drops them with a warning (accepted by the brief). An SDK root outside home emits nothing. Likewise for AVD snapshots under a custom `$ANDROID_AVD_HOME`.

## Questions

1. **Who applies `stale_days` for generic `children` recipes (e.g. `xcode.derived_data`, 30 days)?** I assumed the P3-W3 classifier does it from `Finding.LastUsed`. If not, `children` needs a stale filter, which is a contract change to `registry.go`.
2. **What should Target be for native findings?** I left it empty for the aggregate unavailable-simulators finding, and for runtimes I used the runtime's own `path`, which is outside home. If the classifier or plan fingerprints `Target` for native items, please confirm what it expects.
3. **Can the contract say, in `docs/ORCHESTRATION.md` or a lint, that detector files must not end in a GOOS or GOARCH suffix?** Examples are `_android`, `_ios`, `_linux` and `_arm64`. The `_android` case bit this brief.
