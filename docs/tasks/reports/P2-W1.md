## Design

**Queue.** `Workers` goroutines (default 4, clamped 1..16) share one mutex-guarded **LIFO stack** of pending directories, plus a `sync.Cond`.
- A worker pops a dir, lists it, and pushes its subdirectories.
- A worker exits when the stack is empty and no worker is active, or on cancel.
- Pushing never blocks because the stack is a slice, not a fixed channel. So there is no producer/consumer deadlock on deep trees, no recursion, and no goroutine per directory.
- LIFO makes the walk roughly depth-first. The frontier stays around depth × fan-out instead of a whole BFS level.

**Listing.**
- `os.OpenFile(dir, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)`.
- `fstat` on the fd must match the `(st_dev, st_ino)` the parent saw. On a mismatch the dir was swapped mid-scan and is ignored.
- `Readdirnames` reads in batches of 512, so huge directories are never fully in memory and cancel is checked between batches.
- Each entry is stat'ed with `unix.Fstatat(dirfd, name, AT_SYMLINK_NOFOLLOW)`: no path joins per file, symlinks never followed.
- Path strings are built only for directories, kept files, Skip/Opaque candidates and errors.

**Aggregation (streaming, bottom-up).**
- Each pending `dir` has a parent pointer and a `pending` count: 1 for its own listing plus 1 per unfinished subdirectory.
- When the count reaches 0, the dir is finished:
  - it is kept if it is the root, or if it isn't an Opaque descendant and (`Bytes >= KeepThreshold` or `Keep(mapped)`)
  - its totals (bytes, files, mtime max) fold into the parent
  - the parent may finish in turn
- Finished dirs are unreferenced, so only the frontier, its ancestors and the kept nodes are in memory.

**Memory bounds.** Memory scales with:
- the frontier (LIFO)
- the number of kept nodes
- the hard-link set, which holds only inodes with `nlink > 1` that still have unseen links. An entry is deleted when its last link is seen.
- Unmeasured entries

It does not grow with the number of files below the threshold. Peak heap on the synthetic tree is about 4.3 MB at 100k and at 200k files.

**Other details.**
- **Skip/Opaque:** lowercased sets. Only directories whose lowercased path is the parent of a Skip/Opaque path (`watch`) lowercase their children's paths. Other directories pay nothing.
- **Cancel:** a watcher goroutine sets a stop flag and broadcasts. Workers finish their current batch and exit. Directories still on the stack are then released, so their own blocks and everything already finished roll up to the root. The result is a consistent partial tree with `Incomplete=true`. If `ctx` is already canceled, no directory is listed at all.
- **Progress:** one ticker goroutine reads atomic counters and the current dir, so calls are never concurrent and come at most once per `ProgressEvery`. All goroutines are joined before `Scan` returns.
- **Priority:** `SetBackgroundPriority` = `unix.Setpriority(PRIO_DARWIN_PROCESS, 0, PRIO_DARWIN_BG)`. `Scan` never changes priority.

- Test coverage maps to the brief:
  - Sizes: sparse ≈ 0, hard link once, limit 1 → counted again plus `HardlinkLimitHit`, symlink to a 4 MB dir adds ~0, totals equal an independent `WalkDir`+`Lstat` oracle
  - Keep rules: threshold, `Keep` callback, root always kept, Opaque measured but descendants never kept (and `Keep` is never called for them), Skip on dirs and files, case-insensitive matching with a trailing slash
  - Mapping: Nodes, Unmeasured, Progress and `Keep` input, plus `mapPath` edge cases and the `DataVolume` default (pre-canceled, so only the root is lstat'ed)
  - Errors: a `0o000` dir and a read-only, no-search `0o400` dir each give one permission Unmeasured while the rest is counted; missing, file and symlink roots return errors; injected EIO → Unmeasured, ENOENT → ignored
  - Cancellation: cancel mid-walk returns in under 1 s with partial totals and the root present, and the goroutine count settles
  - Concurrency: Workers 1, 4, 16, 0 and 99 give identical results, and identical to the oracle
  - Progress: never concurrent, rate-bounded, mapped, monotonic
  - Mtime propagation, file nodes (kind, depth, files), sort ties broken by path

The per-entry stat goes through a package-level hook (`fstatat`). `TestCrossDevice` reports a different `st_dev` for `mnt` and checks it is neither descended nor counted. ## Deviations and choices to confirm
1. **Benchmark size:** the default is ~100k files / 10k dirs. Building the 200k tree takes about 5 minutes, which risks the foreground time limit. The full size is available with `MACDOC_BENCH_FULL=1`; numbers for both are above. The tree is built once in the outer benchmark, and only the `b.Run("scan")` sub-benchmark is timed.
2. **Hard links and `Files`:** a de-duplicated link adds neither bytes nor a file count, so `Files` counts distinct inodes. Past the limit both are counted per link.
3. **Hard-link set eviction:** an inode is removed from the set once all `nlink` links have been seen. So `HardlinkLimit` caps *concurrently tracked* pairs, not pairs ever seen. This is within the contract wording, and it keeps memory small.
4. **MtimeMax** includes each directory's own mtime and the mtimes of symlinks and other non-regular entries, not only regular files. So an empty dir still has a meaningful staleness value.
5. **Cross-device entries:** a directory on another device (a mount point) is neither descended nor counted, not even its own inode.
6. **Unmeasured reasons:**
   - For non-permission errors, the reason is the underlying errno text (`PathError.Err`), e.g. "input/output error", not the full `err.Error()`. That would repeat the *unmapped* path, which is already in `Unmeasured.Path` (mapped).
   - A directory that can be read but not searched (no `x` bit) gives one Unmeasured for the directory, not one per entry.
7. **Errors ignored silently, like ENOENT:** `ENOTDIR` and `ELOOP` (the entry was replaced mid-scan by a file or symlink), and a dev/ino mismatch on open.
8. **Root in Skip** is ignored: the root is always scanned. **Root in Opaque** works: nothing below it is kept.

## Questions
1. Is counting `Files` once per hard-linked inode (item 2) right for the store, or should `Files` count every link?
2. `Keep` runs under the scanner's aggregation mutex (once per finished directory). That's fine for a cheap matcher. If Phase 3's recipe/project matcher turns out to be expensive, it should be precomputed (e.g. a set or trie) rather than called per dir.
