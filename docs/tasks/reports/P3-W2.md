**nvm default resolution:** reads `~/.nvm/alias/default`. A version prefix (`24`, `v24`, `v24.22`, `v24.22.0`) resolves to the newest installed match; `node`/`stable` resolve to the newest. Other values are followed as alias files (e.g. `lts/iron`), up to 5 hops, rejecting `..` and absolute paths. If no default file exists, only the newest is excluded. If the default exists but can't be resolved (`lts/*`, a missing alias, a loop, a version that isn't installed), **nothing is emitted**, since any version might be the default. Real fixture (v20.20.2, v24.22.0) with default `24` → v20.20.2.

**LM Studio:** `keep_children_of` keeps the publisher directories. Publisher names aren't known statically, so the `<publisher>/<model>` directories are found by a two-level walk of `env.Nodes`. The scan keeps them only at or above its keep threshold (100 MB by default). Models are normally GBs, but smaller ones are missed (recorded in `confidence_notes`).

**Staleness:** `node_modules_stale`, `venv_stale` and `downloads_large_old` filter on `stale_days` themselves, as the brief asks. The other detectors (generic `children`, `lmstudio_models`, `ollama_models`, `app_caches`) set `LastUsed` and leave staleness filtering to the classifier (P3-W3).

## Assumed tool output shapes (my fixtures)

- `w2_docker_system_df.txt`: `docker system df --format {{json .}}`. One object per line, with string fields `Type`, `TotalCount`, `Active`, `Size`, `Reclaimable`. Reclaimable may carry ` (45%)`. Sizes are decimal (go-units: `B`, `kB`, `MB`, `GB`). `TotalCount`/`Active` are decoded as `json.Number`, so quoted or bare numbers both work.
- `w2_docker_dangling.txt`: `docker images -f dangling=true --format {{json .}}`. One object per line; only `ID` and `Size` are used.
- Docker daemon down: real `docker_not_running.txt` ("failed to connect to the docker API …") plus the classic "Cannot connect to the Docker daemon …". Any non-zero exit whose output contains "connect" together with "daemon" or "docker api" gives `nil, nil`. Other failures are errors.
- `w2_ollama_list.txt`: header `NAME ID SIZE MODIFIED`. SIZE is `"<n> <unit>"`, two fields, decimal. Glued `4.7GB` also works. MODIFIED is usually relative ("3 weeks ago") and then stays unknown, and the text goes in Note. Absolute `2006-01-02`, `2006-01-02 15:04:05` and RFC 3339 dates are parsed into LastUsed.
- `w2_ollama_not_running.txt`: "Error: could not connect to ollama app, is it running?" with exit 1 gives `nil, nil`.
- `w2_brew_autoremove_n.txt`: `==> Would autoremove N unneeded formulae:` followed by one formula per line. "Would uninstall" headers are also accepted. Empty output means nothing to remove.
- `w2_conda_clean_dry_run.txt`: lines `Will remove N (X.Y MB) <kind>(s).` (binary units, conda `human_bytes`). Lines with no size, such as index caches, are ignored.
- `w2_tmutil_snapshots.txt`: `Snapshots for disk /:` followed by `com.apple.TimeMachine.<date>.local` lines.
- brew cleanup (real fixture): the plan is on stdout and the warnings on stderr. The detector parses both. Binary units, matching Homebrew's `disk_usage_readable`.

## Deviations

1. **`ollama.model` is advise, not native.** `lintArgv` forbids `"rm"` as *any* argv element, so `[ollama, rm, "{id}"]` fails `Load()`, and I may not edit `load.go`. The detector already fills NativeArg from the listing, so switching back only needs the YAML change once the lint allows it.
2. `user.app_caches` also excludes `Homebrew`, because `brew.cleanup` owns `~/Library/Caches/Homebrew`.
3. `docker.dangling_images` uses `SourceEstimated` (with a reason), because summing per-image sizes can double-count shared layers.
4. `docker.volumes` (advise) reports the total volume Size rather than Reclaimable, because the useful number for review is how much the volumes hold.
5. Shared test helpers have a `w2` prefix (`w2Run`, `w2Fixture`, `w2Fake`, …) to avoid name clashes with P3-W1 in the same package. Production helpers in `detect_system.go` use plain names: `stale`, `parseSize`, `firstLine`, `plural`, `requireParam`, `belowHome`, `projectDirs`, `runDryRun`, `errNoDryRun`. **If P3-W1 defines any of these, the merge will fail to compile**; rename one side.

**Required fix: `node_modules_stale` flagged tool installs.** Changes:

- (a) In `projectDirs`, shared with `venv_stale`: the first component below home must not start with `.` and must not be `Library` (case-insensitive).
- (b) The parent directory must not be named `lib`, so no `…/lib/node_modules`. node_modules is always the last component and has no node_modules ancestor, so this matches exactly the `lib/node_modules` segment pair.
- (c) The parent must contain `package.json` and one of `package-lock.json`, `npm-shrinkwrap.json`, `yarn.lock`, `pnpm-lock.yaml`, `bun.lockb` or `bun.lock`, all checked with `os.Lstat` as regular files. Symlinks and directories don't count.
- (d) `params.min_bytes: "50000000"` is set in `node.yaml`, and the code default is also 50,000,000.
- (e) `LastUsed` is the newest of the folder's MtimeMax and the package.json and lockfile mtimes, and staleness is judged on that value. A folder with an unknown MtimeMax and an old package.json and lockfile is therefore dated by those files.

**`venv_stale`:**
- (a) Same first-component rule, via `projectDirs`.
- (c) The parent must hold, as a regular file, one of `pyproject.toml`, `requirements.txt`, `requirements-*.txt`, `setup.py`, `setup.cfg`, `Pipfile`, `poetry.lock` or `uv.lock`. This is checked with one `os.ReadDir` of the parent, using names and entry types only (no file reads).
- The `pyvenv.cfg` `os.Lstat` check is unchanged.

The `confidence_notes` in both YAMLs now describe these rules.
