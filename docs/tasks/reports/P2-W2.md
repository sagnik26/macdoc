## Schema (v1)
```sql
CREATE TABLE schema_migrations (version INTEGER PRIMARY KEY, applied_at INTEGER NOT NULL);

CREATE TABLE scans (
  id TEXT PRIMARY KEY, root TEXT NOT NULL,
  started_at INTEGER NOT NULL, finished_at INTEGER,          -- unix nanos, NULL while running
  status TEXT NOT NULL CHECK (status IN ('running','complete','incomplete')),
  total_bytes INTEGER NOT NULL DEFAULT 0, total_files INTEGER NOT NULL DEFAULT 0,
  unmeasured_count INTEGER NOT NULL DEFAULT 0, macdoc_version TEXT NOT NULL);
CREATE INDEX scans_started_at ON scans (started_at);

CREATE TABLE nodes (
  scan_id TEXT NOT NULL REFERENCES scans (id) ON DELETE CASCADE,
  path TEXT NOT NULL, path_fold TEXT NOT NULL, kind TEXT NOT NULL,
  bytes INTEGER NOT NULL, files INTEGER NOT NULL, mtime_max INTEGER NOT NULL,
  depth INTEGER NOT NULL,      -- absolute component count of path ("/" = 0); used by MaxDepth
  rel_depth INTEGER NOT NULL,  -- model.Node.Depth as reported by the scanner (round-trips)
  PRIMARY KEY (scan_id, path_fold));
CREATE INDEX nodes_scan_bytes ON nodes (scan_id, bytes DESC);

CREATE TABLE unmeasured (
  scan_id TEXT NOT NULL REFERENCES scans (id) ON DELETE CASCADE,
  path TEXT NOT NULL, reason TEXT NOT NULL);
CREATE INDEX unmeasured_scan ON unmeasured (scan_id, path);
```

## Design choices
- **Open**
  - Runs `MkdirAll(dir, 0700)`, then `OpenFile(O_RDWR|O_CREATE, 0600)`. If the existing file's mode is looser than 0600 it is chmodded to `mode & 0600`. A tighter mode (for example 0400) is left alone.
  - Existing parent directories are **not** re-moded, because the parent might be `~/Library/Application Support` or a directory the user chose.
- **DSN**
  - The DSN is `file:` plus the URL-escaped path, so paths with spaces such as `Application Support` work. This is tested.
  - It sets `_pragma=journal_mode(WAL)`, `busy_timeout(5000)`, `foreign_keys(ON)`, `synchronous(NORMAL)` and `_txlock=immediate`.
  - Pragmas are in the DSN so that every pooled connection gets `foreign_keys` and `busy_timeout`, which are per-connection settings.
  - `BEGIN IMMEDIATE` means a write transaction never fails on a lock upgrade.
- **Concurrency**
  - `SetMaxOpenConns(4)`. WAL lets readers run while one writer works.
  - All in-process writes, including migrations, are serialized by `Store.writeMu`. The SQLite write lock is therefore only contended by another process, and `busy_timeout` covers that case. This is tested with two handles on the same file.
- **Migrations**
  - Each migration runs in its own immediate transaction, together with its `schema_migrations` row.
  - The current version is read inside the transaction, so two processes opening at once can't apply a migration twice.
  - A version higher than the code knows gives `database schema version N is newer than this macdoc supports`.
- **Times** are stored as INTEGER unix nanoseconds and read back as UTC. `finished_at` is NULL while a scan is running, which gives a zero `FinishedAt`.
- **IDs**
  - An ID is `S-` plus unpadded StdEncoding base32 of 5 bytes from `crypto/rand`, which is exactly 8 uppercase characters.
  - The insert uses `ON CONFLICT(id) DO NOTHING`. If `RowsAffected == 0` it retries, up to 8 attempts. `randRead` is a package variable so tests can force collisions.
- **Fold** is `strings.ToLower(norm.NFC.String(p))`.
  - A prefix is `path.Clean`ed first (so a trailing `/` is ignored), then folded.
  - Matching is `path_fold = p OR path_fold LIKE escape(p) || '/%' ESCAPE '\'`.
  - A prefix of `/` matches everything. `History` uses an exact match on the cleaned, folded path.
- **Nodes**
  - The SQL text is fixed: unused filters are turned off by their parameters. This also satisfies gosec G202.
  - Results are ordered `bytes DESC, path ASC`. `MaxDepth` filters `depth <= depth(prefix) + MaxDepth`. `LIMIT -1` means unlimited.
  - Empty results are non-nil (`[]`) so JSON output shows `[]`, not `null`.
- **Writes on non-running scans**
  - `AddNodes`, `AddUnmeasured` and `FinishScan` read the scan's status inside the write transaction. A missing scan returns an error wrapping `ErrNoScan`. A finished scan returns `scan S-… is complete, not running`.
  - A failed batch rolls back completely.
- **FinishScan** accepts only `complete` or `incomplete`. It sets `unmeasured_count` from `COUNT(*)` of the stored rows in the same UPDATE.
- **Reads on a scan ID that doesn't exist:** `Nodes` and `Unmeasured` return an error wrapping `ErrNoScan`. They don't return an empty list.
- **LatestScan** breaks ties on `started_at` by insertion order (`rowid DESC`). `History` uses the same tie-break.
- **PruneScans**
  - Runs in one transaction. It reads `MAX(started_at)` of complete scans first, deletes complete scans that aren't among the newest `keep`, then deletes incomplete scans started before that time.
  - Running scans are never touched. The cascade removes their nodes and unmeasured rows.
  - Afterwards it runs `PRAGMA wal_checkpoint(TRUNCATE)`. There's no VACUUM.
  - `keep < 0` is an error. `keep == 0` removes every complete scan.
- **No file deletion or exec.** forbidcheck is clean.

## Deviations
1. **Extra column `nodes.rel_depth`.**
   - The brief says MaxDepth works from a stored per-node depth and a prefix depth counted from its components, with `/` = 0. That only works if node depth is the absolute component count, so `depth` stores that.
   - `model.Node.Depth` is documented as "components below the scan root", which is different whenever the root isn't `/` (for example `~`, or a firmlink root). I store it unchanged in `rel_depth` so `Nodes` returns exactly what the scanner reported.
2. **Extra index `unmeasured(scan_id, path)`**, which serves `Unmeasured`'s ORDER BY and the count in FinishScan.
3. **`go.mod` is not changed** (it isn't in my allowed files). `go mod tidy -diff` wants `modernc.org/sqlite` moved to a direct requirement, plus some go.sum lines. Build, test and lint are unaffected.

2. Is `rel_depth` acceptable? The alternative is to make the scanner's `Depth` absolute and drop the column.
3. `History` filters on `path_fold` without its own index, so it scans the nodes of all stored scans. That's cheap at today's sizes, around 50k nodes × a few scans. Should a `nodes(path_fold)` index be added when `trend` lands? It costs insert time.
