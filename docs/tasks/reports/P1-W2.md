# P1-W2 report: disk, APFS container, local snapshots, purgeable

Commit: `de67a5d` on `task/P1-W2` (not pushed or merged).

## Summary
- Deleted `internal/probe/stubs_w2.go` (`git rm`). Its signatures are now real functions in:
  - `internal/probe/disk.go`: `ParseDiskutilInfo`, `ParseAPFSList` and `CollectDisk`, plus a shared `runRead` helper (wraps run errors and non-zero exits with the command key and trimmed stderr).
  - `internal/probe/snapshots.go`: `ParseLocalSnapshots` and `CollectSnapshots`.
- Plists are decoded with `howett.net/plist`. Pointer fields tell an absent key apart from a zero value, which the `TotalSize`/`FreeSpace` fallbacks need. In the real fixture `FreeSpace` is `0` and `APFSContainerFree` is set.
- Commands use fixed argv only: `diskutil info -plist /` and `diskutil apfs list -plist` (15 s timeout each), and `tmutil listlocalsnapshots /` (default timeout). No mutating subcommands and no shell.
- **Partial results (documented on `CollectDisk`):**
  - If `diskutil info` fails, or isn't APFS, you get a zero `Disk` plus an error, and the apfs list is not run.
  - If only `apfs list` fails (run error, non-zero exit, bad plist or container not listed), you get `ContainerRef`, total, free and `PurgeableBytes` filled in, `Volumes == nil`, and an error prefixed `disk volumes unavailable:` that the caller can show as a warning.
- `ParseAPFSList`:
  - Volumes with no `Roles` key get `[]string{}`, so the JSON shows `[]` rather than `null`.
  - The sort is stable by `UsedBytes` descending.
  - `MountPoint` is filled only when it's in the plist. The real `apfs list` fixture has none.
- `ParseLocalSnapshots` skips:
  - the `Snapshots for …:` header
  - blank lines
  - "no snapshots" messages (lines containing "snapshots" that start with "no " or contain " no ")

  It always returns a non-nil `Names`. It errors only if the scanner fails (a line over 64 KiB).

## Purgeable approach
- `internal/platform/darwin/purgeable_cgo.go` (`darwin && cgo`) is a tiny Objective-C function inside `@autoreleasepool`. It reads `NSURLVolumeAvailableCapacityForImportantUsageKey` and `NSURLVolumeAvailableCapacityKey` for `/`, then returns important minus available, clamped at ≥ 0.
  - Only autoreleased objects are used: no alloc/retain, so nothing to leak.
  - There's no exec, and the path `/` is fixed.
- `purgeable_stub.go` (`!darwin || !cgo`) returns `(0, false)`.
- `CollectDisk` returns `{Value: n, Source: measured}` when ok, and `{Source: unknown, Reason: "purgeable space needs the cgo build"}` otherwise.
- In probe tests the shim goes through a package var (`purgeableBytes`), so they're deterministic.
- **Value on this Mac:** 2,903,612,127 bytes (about 2.9 GB), logged by `TestPurgeableBytesCgo`.
