# P6-R1 report: red-team of `internal/executor`

**Scope:** tests only, in `internal/executor/redteam_test.go`. No production code changed. Base: `2933e0f` (main, after P9-R1).
**Safety:** every test runs in the executor package under TestMain's `MACDOC_SANDBOX`, with fixture homes inside the sandbox. Native commands only reach the fake `Exec` and `platform.FakeRunner`. The one real process a test starts is `hdiutil` / `umount` (F1), and it only acts on a 2 MB disk image the test creates in `t.TempDir()`, which is detached in cleanup. No cleanup tool was run, and nothing was built or run against the real home.
**Result:** no path was found that deletes user data outside the recipe allowlist. 8 findings (8 failing tests). Two are Medium: a mounted volume inside a target is moved along with it, and the content check ignores case. One more Medium: a symlinked quarantine root makes apply write into, and move a target into, a protected folder. The rest are Low. 15 attacks held and stay as passing regression tests.
**Gates:** `go test -race ./internal/executor/... ./internal/planner/... ./internal/quarantine/...` fails only on the 8 `TestRedteamBroken*` tests. Every existing test and every `TestRedteamHeld*` test passes. `make lint` (0 issues), `make importcheck` and `make forbidcheck` pass.

Severity: **High** means it deletes or moves something it shouldn't, outside the allowlist or the protected-path rules. **Medium** means it defeats a safety check but fails closed or needs unlikely conditions. **Low/Info** covers everything else.

| F1 | Medium | **The checks and the move cross onto another volume.** Only the target's own `dev` is compared with the quarantine's. Input: `~/Library/Logs/A` with an HFS+ disk image mounted at `A/mnt` (`hdiutil attach -mountpoint`, which needs no root; FUSE, SMB and sshfs mounts behave the same), planned as `user.logs`, applied with `DeleteNow`. ## Notes (not findings, untested)

- **Vendored exemption.** Anything below a `node_modules` or `site-packages` component *below the target* goes unchecked: `~/Library/Caches/x/node_modules/myproj/.git` would be deleted. This is documented (§4.3). When the target itself is `node_modules` (`node.node_modules`), its direct children are checked, so a repo cloned into `node_modules/foo` is refused. Consider limiting the exemption to depth ≥ 2, or checking for `.git` anywhere outside `node_modules/.pnpm`-style stores.
- **Purge vs restore race.** On darwin, `os.RemoveAll` works through directory fds. If `quarantine restore` renames the payload out while a `purge` of the same ID is inside `RemoveAll`, the restored folder can be emptied in its original place. Two concurrent user commands on one ID are needed, and there's no hook to make it deterministic, so it isn't demonstrated. Suggested fix: an `flock` on the entry, as `store.LockPlans` does for plans.
- **Crash during the DeleteNow purge.** `RemoveAll` may delete `manifest.json` before the payload. A crash then leaves a *damaged* entry that macdoc will never purge, so the space is lost until the user deletes it by hand. Removing `payload/` first and the manifest last would keep the entry purgeable.
- **Restore doesn't re-check the policy.** With a forged store row plus manifest (write access to the state dir needed), restore can create a new folder inside a protected place. It never overwrites, so nothing is lost.
- **Tool binaries are resolved through `PATH` at exec time** (`exec.CommandContext("brew", …)`). A different `brew` earlier on `PATH` would run. That's outside macdoc's control. Resolving and pinning absolute paths at plan time would narrow it.
- **The executor doesn't enforce per-item approval for Claude plans or RISKY items.** It trusts `approved`. Both callers (`apply.go`, `tui_remove.go`) are correct today. A defense-in-depth check in `Apply` (refuse a Claude-origin plan whose approved set came from a batch path) would keep it that way.
- **Inode reuse** after delete and recreate isn't exercisable on APFS (object IDs aren't reused). Paths over `PATH_MAX` and folders with more than 500k entries weren't tested (cost). Both fail closed in the code (`Lstat` error, and the entry count).
