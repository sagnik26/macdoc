## Rules implemented (`engine.Opportunities`)

- **Scan**
  - Uses the latest **complete** scan. With none, it returns `engine.ErrNoScan` (`no scan yet. Run "macdoc scan" first`); incomplete scans are ignored.
  - If the scan is older than 6 h it adds the warning `results are from a scan N hours old; run "macdoc scan" to refresh`.
  - It never scans by itself. `ScanAge` is "just now", "Nm ago", "Nh ago" or "Nd ago", measured from `FinishedAt`.
- **Detectors**
  - Concurrency is bounded at 4, and each detector gets `context.WithTimeout(90 s)`.
  - A detector that ignores its context is abandoned at the timeout and becomes a warning (`<id>: detector stopped after 90s: …`).
  - Errors (`<id>: <err>`), panics (`<id>: detector panicked: …`) and unknown detector names also become warnings, and the other detectors keep running.
- **Native findings**
  - Dropped silently if `recipes.ToolInstalled(argv[0])` is false.
  - `{id}` is replaced in both `Argv` and `DryRunArgv`. The finding is dropped with a warning if `NativeArg` is empty, or contains whitespace, a control character, any of ``/;|&$`<>(){}*?[]'"\``, or a leading `-`.
  - The identifier is only checked when the argv actually contains `{id}`.
  - Fills `Command` and `DryRun`.
- **Quarantine findings:** one `safety.NewPolicy(home, nil)` per run. A finding is dropped with a warning (`<id>: skipped <target>: <violation>`) unless `CheckTarget(target, recipe.Allow)` is nil.
- **Advise findings:** kept as they are.
- **Staleness**
  - `IdleDays` is the number of whole days since `LastUsed`, or -1 when unknown.
  - With `StaleDays > 0`: a known idle time below `StaleDays` drops the finding, and an unknown one multiplies confidence by 0.5.
- **Risk:** a SAFE item whose idle time is known and under 7 days becomes CAUTION. Risk is never lowered. `engine.RaisedFrom(op, catalog)` gives `explain` the base risk.
- **Confidence:** measured 1.0, tool 0.9, estimated 0.6, unknown 0.3. A `Bytes.Source` of `""` is normalized to unknown.
- **Overlap**
  - Actionable means native or quarantine with a non-empty target.
  - An actionable item whose target is strictly below another actionable target is dropped. Paths are compared component by component, case-insensitively and NFC-normalized.
  - The warning reads `N item(s) inside another listed folder were merged into it`.
  - Advise items never absorb others and are never absorbed.
- **ID**
  - The ID is `O-` + lowercase base32(sha256(scanID␀recipeID␀target␀nativeArg))[:6]. It is deterministic per scan and changes with the scan.
  - Colliding IDs are all extended to 8 characters, then by 2 more while they still collide.
  - Exact duplicate findings (same recipe, target and identifier) are removed first.
  - `FindOpportunity` accepts `O-xxxxxx`, `o-xxxxxx` or `xxxxxx`, in any case.
- **Title:** the finding's title. Otherwise the recipe title, plus ` · <base name>` for multi-instance recipes (see deviations).
- **Ranking:** tiers in the order SAFE, CAUTION, RISKY, ADVISE. Within a tier, by `Bytes.Value × Confidence` descending, then by ID.
- **Totals:** known bytes per final risk; unknown sizes are never counted.

### Storage (`engine.Storage`)

- **Categories:** totals per category, with count, unknown count and known bytes per risk.
- **System Data**, from `probe.CollectDisk` and `probe.CollectSnapshots` through the Runner:
  - local snapshots: the count is in the name and the size is unknown with a reason, because macOS doesn't report it
  - the VM volume's `UsedBytes` (swap and sleep image)
  - purgeable bytes
  - "not visible to the scan": Data volume used minus the scan total, marked estimated
  - `/private/var/folders` and `/Library/Developer/CoreSimulator` from the scan's nodes
- Anything that can't be read is reported as **unknown with a reason**, never as 0, and probe errors become warnings.
- **`--large`:** `Largest(nodes, 0, 1 GB)`, excluding nodes equal to or below any opportunity target, then capped at 20.

## Deviations

1. **Multi-instance titles.** The brief doesn't define "multi-instance". I add ` · <base name>` when the recipe's detector is `children`, or when the detector produced more than one finding in this run.
   - When the base name is one of the recipe's `keep_names` (e.g. `node_modules`), the parent's name is used instead, giving `Stale node_modules folder · myapp`. Otherwise every line would read `· node_modules`.
2. **Extra result fields.**
   - `StorageResult` also has `ScanAge` and `Warnings`, so probe failures and detector warnings aren't lost.
   - `CategoryTotal` has `UnknownCount`.
   - New exported helpers: `ErrNoScan`, `TierOrder`, `FindOpportunity`, `ByToolchain`/`ToolchainTotal`, `RaisedFrom`, `FormatAge`, `Categories`, `StorageOptions`.
   - New CLI result types: `DevResult` and `ExplainResult` (the latter includes `base_risk`).
3. **`--large` also skips `/private/var/folders` and `/Library/Developer/CoreSimulator` themselves,** since they're already in the System Data section with an explanation. Only exact matches are skipped, not their children.
4. **Restore note on each line.**
   - rebuild → `rebuilds on next build`
   - redownload → `re-downloads on demand`, or `re-download ~X` when `redownload_bytes` is set
   - otherwise `restore.note` truncated to 40 characters, or `can't be restored` for irreplaceable
   - Advise items always show their note (e.g. "Finder › iPhone › Manage Backups"), matching the mockup.
5. **Sizes and totals.**
   - Estimated sizes are shown as `~11.0 GB` and unknown as `—`.
   - A tier total made only of unknown sizes reads `size unknown`, and a mix reads `X + unknown`, so unknown is never shown as `0 B`.
6. **Grouped line format.** It is `<n> × <recipe title> · <sum>` in the title column, with `(macdoc wins --all)` in the restore column and a blank ID.
   - `dev <toolchain>` lists every item without grouping; plain `dev` groups like `wins`.
7. **`dev brew`** is accepted as an alias for `homebrew`, as `docs/CLI_UX.md` §1 lists `brew`.
8. **JSON warnings.** `writeJSON` has no warnings parameter, so warnings live inside `data` (`data.warnings`), not in the envelope's top-level `warnings`.
9. **No color.** The output has no color yet, to match `doctor`. The tone rules allow it, but nothing else uses lipgloss so far.

## Questions

1. **Same target from two recipes isn't merged.** The overlap rule only drops *strict* descendants, so two actionable recipes reporting the same path are both listed and both counted in totals. Today `user.app_caches` excludes the folders other recipes own, so I haven't seen this happen. Should equal targets be de-duplicated, for example keeping the lower-risk or the first recipe?
2. **`docker.unused_images` and `docker.dangling_images` overlap (P3-W2 Q4, "handled in the classifier").** The P3-W3 brief has no rule for this, and both findings have an empty target, so the overlap merge can't see them. I didn't invent one, so SAFE + CAUTION totals can double-count dangling images. Should the classifier drop `dangling_images` when `unused_images` is present, or subtract it?
3. **Recipe-level staleness for aggregate native findings.** `StaleDays` combined with unknown `LastUsed` halves confidence. That's fine for ranking, but there's no stale filter for native aggregates (e.g. `docker.build_cache`), which never have `LastUsed`. Is that intended?
4. **The ID formula differs between documents.** `docs/DEVELOPMENT_PLAN.md` §4 Phase 3 says `base32(sha256(recipe_id + canonical_target + scan_id))[:6]`. The brief says scanID␀recipeID␀target␀nativeArg, lowercase. I followed the brief. Should the plan doc be updated to match?
5. **The envelope's `warnings` field.** Should `writeJSON` take warnings so they land at the top level as `docs/CLI_UX.md` §4 describes? That would be a small `root.go` change outside my allowed edit.

## Review round 2

New commit `821ab86` on `task/P3-W3` (no amend). Tech-lead answers noted: Q3 is intended, and the tech lead will update the plan doc for Q4. Deviations 1–9 are accepted.

1. **Unknown idle time is now dropped.** When `StaleDays > 0` and `IdleDays` is -1, the finding is dropped instead of having its confidence halved. The count is reported once as `N item(s) skipped because their last use is unknown`, and the 0.5 factor is gone. The test (`TestStalenessRiskAndConfidence`) covers 2 such items, the single warning and updated totals.
2. **Reserved identifiers are rejected.** `checkNativeArg` also rejects `all`, `unavailable`, `booted`, `help` and `version`, compared case-insensitively. The finding is dropped with a warning (`… is a reserved word the tool may treat as a selector`). Tests: `TestNativeDropRules` (`Unavailable`, `ALL`) and `TestCheckNativeArgAndSubstitute`.
3. **Equal targets across recipes.** `dropEqualTargets` runs after exact de-duplication and before the overlap merge. Targets are compared after folding (case-insensitive, NFC, cleaned).
   - Among actionable items it keeps the higher risk, then the lower recipe ID.
   - It warns `<dropped recipe> duplicates <kept recipe> for <target>`.
   - Findings of the **same** recipe on the same target are left alone, since they differ only by tool identifier (exact duplicates are already removed).
   - Advise items are never deduplicated.
   - Tests: `TestEqualTargets` (risk wins, ID tie-break, case difference, native vs quarantine, advise untouched, 4 warnings) and `TestEqualTargetsSameRecipeKept`.
4. **Containment table.** It has one entry: `docker.unused_images` contains `docker.dangling_images`.
   - When both are present and both sizes are known, the container's bytes drop by the contained sum, with a floor of 0.
   - The source becomes the weaker of the two (measured > tool > estimated > unknown), and confidence is recomputed from it.
   - The Note gets `excludes dangling images listed separately`, joined with `; ` if a note already exists.
   - If either size is unknown, nothing changes.
   - Test: `TestContainedBytesSubtracted` covers the subtraction, the 0 floor with an existing note, unknown contained, unknown container and container alone.
5. **Envelope warnings.** `root.go` has a new `writeJSONWarn(w, command, data, warnings)`, and `writeJSON` now calls it with nil, so `doctor`, `scan` and `version` are unchanged.
   - `wins`, `dev`, `storage` and `explain` put their warnings in the top-level `warnings` field. `data.warnings` stays for `wins`, `dev` and `storage`.
   - Test: `TestEnvelopeWarnings` covers all four commands, plus `doctor`/`version` JSON still working and `version` omitting `warnings`.

**Results:** `go test -race ./...` passes, `golangci-lint run ./...` shows 0 issues, and `make importcheck forbidcheck` passes. Coverage is `internal/engine` 92.9% and `internal/cli` 92.1%.
