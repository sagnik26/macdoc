## Questions for the tech lead

1. **D3 (a)/(b) reject two catalog patterns.** `~/*/**/node_modules` (`node.node_modules_stale`) and `~/*/**/.venv` (`python.venv_stale`) can match inside `~/Documents` and others. Their first two components are also both wildcards. Applying D3 literally would make the catalog fail to load, which breaks D1's "every recipe must still load". I did **not** weaken the general rules. Instead, an exact-string list `projectTreePatterns` in `load.go` exempts only these two patterns, and only from (a) and (b); (c) and (d) still apply. Their runtime protection is D11 (projectDirs skips protected folders) plus `CheckTarget`. Please confirm, or choose another approach, for example narrower per-root patterns or a pattern-negation feature in `CheckTarget`.
2. **D3 (c) as written rejects every pattern ending in `*`.** `path.Match("*", ".git")` is true. This would reject about 12 catalog recipes (`~/Library/Caches/*`, `~/Downloads/*`, DerivedData, hub, …). I exempt a final component that is exactly `*` **when the pattern has no `**`**: that is, "the children of one fixed folder", where `CheckTarget` rejects `.git`, `.env*` and `*.sqlite*` children at runtime. `~/code/**/*` is still rejected. Please confirm.
3. **D3 runs on `allow` only, not on `keep_children_of`.** `ios.device_backups` (advise-only) lists `~/Library/Application Support/MobileSync/Backup` in `keep_children_of`. That is a read-only scan hint so the advice can show sizes. Applying the protected lint there would reject it. Please confirm.
4. **D6 error semantics.** A FIFO, symlink, directory or oversized `config.ini` or nvm alias is a detector **error** (a warning), not a silent skip. This keeps `TestNvmEdgeCases`' existing "an unreadable alias is a real error" contract, and it fails closed for system images: a hostile AVD config can't make an image look unused.
5. **D5 extra rule.** Besides the four listed checks, the AVD directory must be a real directory, not a symlink (`Lstat`). Otherwise `~/.android/avd/x.avd -> ~/Documents/thesis` would pass every lexical check. Please confirm this is wanted.
6. **D12 note wording.** I read "in both, restore.note says other files 'may be the only copy'" literally. The installer note says that other large downloads aren't included because they may be the only copy. The advise recipe says the file itself may be the only copy.
7. **Docs drift (outside my allowed files).** `docs/RECIPE_CATALOG.md` still shows `python.venv_stale` as CAUTION and has no `user.downloads_large_other` row. `docs/SAFETY_MODEL.md` §1.5 still lists `hf` and `sdkmanager` as delegated tools, and RECIPE_CATALOG still shows the `sdkmanager --uninstall` and `pyenv uninstall` argvs, which the allow-list now rejects. These docs need updating in a doc-owning task.
8. `TestR1SimctlHostileIdentifiersHeld` still has a comment saying `all` is emitted. Since D9 nothing is emitted, and the test still passes. I didn't edit it because its expectations didn't change.
