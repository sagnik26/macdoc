## Attacks tried that held

**Case and Unicode**
- Case variants are all protected: `~/DOCUMENTS`, `~/.SSH`, `~/LIBRARY/MAIL`, `COM.APPLE.*`, `.GIT`, `x.DB`, `X.SQLITE3`, `.ENV.LOCAL`, `/SYSTEM/Library`, `/PRIVATE/etc`.
- **APFS alias brute force.** I created files `a`–`z` and `ab` in a temp dir and `lstat`ed every Unicode scalar, both as a single-rune name and inserted as `a<r>b` (~2.2M probes). APFS treated only **U+017F ſ** as `s` and **U+212A K (Kelvin sign)** as `k`. Full case folding maps both, so `.ſsh` and `.Kube` are protected (`TestRedteamAPFSFoldAliases`). No ignorable code points (ZWJ etc.) alias, so APFS and `fold()` agree.
- Look-alikes are correctly treated as different files, and the FS agrees: full-width `Ｄ`, ZWJ inside `Documents`, Cyrillic `о`, and full-width solidus `／` (one component, not a separator).
- NFD vs NFC: an extra protected path given in NFC is protected when spelled in NFD or upper case.
- Turkish dotless `ı` / `İ`: no APFS alias with `i` was found, and fold keeps them distinct. Consistent.

**Path syntax**
- `..` anywhere (including a trailing `/..`) is rejected.
- `//` and `/./` are cleaned. A trailing `/.` on a non-symlink is cleaned too.
- NUL and relative paths are rejected. `~` isn't expanded in targets.
- Names containing `\n` or `\r` are accepted. That's fine for safety; escaping them in output is a CLI concern.
- `...` is treated as a name.
- Depth rule: `~`, `~/`, `~/x` and `~/./x/.` are all `too-shallow`.
- Very long paths (2000 components, a 300-byte component) return promptly. Each either errors or names something that can't exist.

**Symlinks**
- Symlinks in a parent are resolved: a chain with a relative hop into `~/Documents`, a link to `/`, a relative link climbing out of home into `/private`, a case-varied link into `DOCUMENTS`, and dangling links into `Documents` at depth 1 and 2 (both fail closed).
- A symlink loop returns an error, not a hang.
- A final-component symlink isn't followed, as specified.

**TOCTOU**
- Swapping a parent dir for a symlink after `Canonicalize` changes the canonical path, and a fresh `CheckTarget` rejects it. Note for Phase 6: the executor must re-canonicalize and compare immediately before acting (SAFETY_MODEL §4.3), and should use `O_NOFOLLOW` / `renameatx_np` relative to an opened parent dir fd to close the remaining window.

**Home exception and allow patterns**
- Home exception with a temp home: `/private/etc`, `/private/var/db`, `/var/folders/x`, `/tmp/x/y`, other temp dirs and home's siblings are all still protected. A case-variant spelling of home itself is treated as home.
- Allow patterns:
  - `~/**` and `~/*` can't reach depth 1, and `/**` can't reach `/System` or `~/Documents`.
  - `~/../*/a/b` escapes to a sibling, which is still protected.
  - `~user/…`, relative, empty, NUL and `**/x` patterns never match.
  - Case and NFD mismatches between pattern and path match.
  - `a**` acts as a single `*`, `[` never matches, and `*` doesn't cross `/`.
- Pattern rules: `my.git.repo`, `.gitignore`, `.github`, `x.db.bak` and `data.dbx` aren't protected; `.git` and `sub/.Git/config` are.

**`NewPolicy` and `Within`**
- `NewPolicy` rejects `/`, `/Users`, `//`, `/./`, relative and `..` homes, and `~user`, relative, `..` or NUL extras. A trailing slash on home is equivalent to none. A symlinked home protects `Documents` via the link too.
- `Within` is component-wise and case-insensitive, and rejects relative paths and empty roots.
- Every rejection is a `*Violation`.

**Sandbox**
- Trailing `/`, `//`, `/.`, a leading `//` and case variants all resolve to the same root.
- Rejected, with `active=true` and `Check` failing closed: whitespace-only values, `/`, `/.`, `//`, `..`, home (via a trailing slash, upper case or a symlink), home's parent, a symlink to an ancestor of home, a regular file, a missing dir, `~/sb` and relative values.
- A sandbox dir removed after being set makes every `Check` fail. Re-creating it as a symlink to home is also rejected.
- `HOME` empty or relative makes `Root` error.
- In `Check`: `x/../../outside`, root equality, `//` and name-prefix siblings are refused; case variants of a path inside are accepted.

## Spec ambiguities

- **A1. Set-but-empty `MACDOC_SANDBOX` disables the sandbox** (P0-W2 brief: "unset or empty"). A CI line like `MACDOC_SANDBOX=$(mktemp -d)` that fails, or a typo in the variable name it expands, silently runs executor tests against the real FS. I suggest using `os.LookupEnv` and failing closed when the variable is set but empty. Documented as passing in `TestRedteamEmptyDisables`.
- **A2. `.envrc` and `.env*`.** I argue `.envrc` should be protected. direnv files are user-authored, usually export secrets (API tokens, DB URLs) and aren't regenerable, which is exactly the class `.env` protects. The brief's `.env` / `.env.*` narrowed SAFETY_MODEL's `.env*`; one of the two docs must change (RT-04).
- **A3. Bare git repos** (`foo.git/` directories with `objects/` and `refs/`) are real repositories but aren't protected, because only a `.git` *component* is. The spec says "any `.git` directory". Consider a content check in the executor (a `HEAD` + `objects/` + `refs/` layout means protected), since name matching would wrongly protect `my.git.repo`.
- **A4. "Directories containing protected files can be targets"** (P0-W1 decision on `.db`). This conflicts with RT-01 for *named* roots. I treated named roots (MobileSync/Backup, macdoc state, Containers, extras) as must-not-contain. The tech lead should decide whether `.git` and `.env` inside a candidate directory should block it (`~/code/app` itself is a likely `node_modules`-adjacent mistake).
- **A5. `IsProtected` on non-canonical input** is lexical. That's by contract, but `IsProtected("<link>/x")` misses symlinked parents. Callers must canonicalize first, so consider documenting this more loudly, or have it canonicalize.
- **A6. `..` in extras and patterns is cleaned before `Canonicalize`.** In `extraProtected` and allow patterns, `~/../x/..` is expanded via `filepath.Join`, which silently cleans `..`. For extras this fails closed (it protected home's parent). For patterns it's deferred to the Phase 3 lint, as already decided.
- **A7. Symlinked home and lexical siblings (not testable in a temp dir).** If `/Users/me` links to `/Volumes/X/me`, `NewPolicy` uses the real home. `/Users/me` (the link) and other users' homes under `/Users` then lose the sibling and ancestor protection, since siblings are computed from the real parent. I couldn't demonstrate this under `t.TempDir()`, because everything there is under `/private`. Consider computing sibling and ancestor protection from both the lexical and the resolved home.
