# Task P3-R1: red-team review of the recipe catalog and detectors

**Role:** reviewer (you did NOT write this code) · **Branch:** `task/P3-R1` · **Phase:** 3 · Runs in parallel with P3-W3 (classifier and commands). Don't touch their files.

## Goal
Make a recipe or detector produce something it must never produce:
- a target that could reach user data or protected paths
- a native command that runs something other than the intended tool action
- a detector side effect: a write, a network download, or an unexpected command
- or a crash or hang

Every real finding must become a **failing test**.

## Attack ideas (not exhaustive)
- **Lint bypasses** (`Validate`/`lintPattern`/`lintArgv`):
  - patterns that look deep but match shallow, or match protected areas: `~/*/*` reaching `~/Documents/x`, `~/Library/*`, case tricks, Unicode
  - argv tricks: `--volumes=true`, `-v`, `system`/`prune` split differently, a `{id}` that injects flags (`--all`), tools with dangerous subcommands (`brew uninstall`, `docker rm -f`, `xcrun simctl erase all`, `pod deintegrate`)
  - preconditions with odd args
- **Allow patterns vs. protected paths:** for **each quarantine recipe in the real catalog**, check whether any allow pattern can match a path that `CheckTarget` would accept but that is plausibly user data. Examples:
  - `~/Downloads/*` matching a user's important file: decide whether CAUTION plus the 90-day staleness and 500 MB floor is enough, and argue it
  - `~/Library/Caches/*` matching app data some apps keep in Caches
  - `~/*/**/node_modules` matching a vendored, committed `node_modules`: check that the round-2 rules require a lockfile, which a vendored copy usually also has
  - `~/*/**/.venv`
- **Detector inputs you can craft** (via `fstree` homes, `fakeNodes` and `FakeRunner` output):
  - **simctl JSON:** identifiers with `--all`, spaces, `../`, newlines or very long strings; a key/identifier mismatch; `deletable` missing
  - **ollama list:** names like `-rf`, `x;y`, `a b`, `$(id)`, `--help`, `name\nother`
  - **docker df:** malformed sizes, negative values, huge numbers (overflow to negative)
  - **brew cleanup -n:** a "would free approximately" line with an absurd value, units like `PB`, or missing
  - **nvm aliases:** loops, `../../etc`, absolute paths, symlinked alias files
  - **AVD `.ini` / `config.ini`:** `path=` pointing outside home or into `~/Documents`; `image.sysdir.1=../../`; an AVD name with spaces or shell characters
  - **node and venv:** `package.json` or lockfile as symlinks to elsewhere; `node_modules` as a symlink to `~/Documents` (the scanner never follows symlinks, but can a detector be tricked via its parent?); case-variant names (`Node_Modules`, `.VENV`, `LIBRARY/...`)
  - **DeviceSupport, build-tools, NDK, Gradle version comparison:** versions like `10.0` vs `9.9`, `rc`/`beta`, non-numeric names, so that the *newest* gets emitted for removal
- **Side effects:**
  - Assert that no detector calls the Runner for npm, pnpm or yarn.
  - Assert that every Runner command is in an expected read-only set (`brew cleanup -n …`, `brew autoremove -n`, `docker system df …`, `docker images …`, `xcrun simctl list|runtime list …`, `xcrun --find simctl`, `tmutil listlocalsnapshots /`, `conda clean --dry-run …`, `ollama list`). Run every detector with a recording `FakeRunner` and flag any argv **outside** this set.
- **Robustness:** huge inputs, empty inputs, and a NodeSource that returns errors or unsorted data. No panics.

## Output
1. Tests expected to fail if a bug exists, marked `t.Errorf("BUG: …")`. Tests that document correct behavior should pass.
2. Commit on `task/P3-R1`.
3. `.task/REPORT.md` with:
   - a findings table (ID, severity, description, failing test, suggested fix)
   - the attacks that held up
   - your per-recipe judgment on the riskiest quarantine patterns (`~/Downloads/*`, `~/Library/Caches/*`, `node_modules`, `.venv`, `~/Library/Logs/*`)
   - spec ambiguities
4. `.task/last-test.txt`, e.g. `N BUG tests failing · M passing`

Then stop.
