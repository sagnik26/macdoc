## 1. `engine.Opportunities`
```go
type OpportunityOptions struct {
    Home   string
    StorePath string          // default store.DefaultPath(Home)
    Runner platform.Runner
    Now    time.Time          // default time.Now()
    Catalog *recipes.Catalog  // default recipes.Load()
}
type OpportunityResult struct {
    Scan          model.ScanInfo        `json:"scan"`
    ScanAge       string                `json:"scan_age"`     // e.g. "2h ago"
    Opportunities []model.Opportunity   `json:"opportunities"` // ranked
    Totals        map[model.Risk]int64  `json:"totals"`        // known bytes per risk tier
    Warnings      []string              `json:"warnings,omitempty"`
}
func Opportunities(ctx context.Context, o OpportunityOptions) (OpportunityResult, error)
```
- **Scan:** use the latest **complete** scan. If there is none, return an error: `no scan yet. Run "macdoc scan" first`. If it's older than 6 h, add a warning (`results are from a scan N hours old; run "macdoc scan" to refresh`). Never auto-scan.
- **Run detectors:**
  - Run each recipe's detector with a bounded concurrency of 4.
  - Give each detector a 90 s timeout via `context.WithTimeout`.
  - A detector error becomes a warning (`<recipe id>: <err>`) and doesn't stop the others.
  - Recover panics in detectors into warnings.
- **Per finding (drop rules):**
  - **Native:** drop silently if `recipes.ToolInstalled(argv[0])` is false. Substitute `{id}` with `NativeArg`. **Drop with a warning** if `NativeArg` is empty when the argv has `{id}`, or if it contains whitespace, `/`, a leading `-`, or any of ``;|&$`<>(){}*?[]'"\`` and control characters. Fill `Command` and `DryRun`.
  - **Quarantine:** build one `safety.NewPolicy(home, nil)` per run, then **drop with a warning** unless `policy.CheckTarget(f.Target, recipe.Allow)` is nil. This is defense in depth: detectors may be wrong.
  - **Advise:** keep as is. The target is informational and may be outside home.
- **Staleness:**
  - `IdleDays` = whole days since `LastUsed`, or -1 if unknown.
  - If `recipe.StaleDays > 0` and the idle days are known and below StaleDays, **drop** the finding.
  - If they're unknown, keep the finding but multiply its confidence by 0.5.
- **Risk:** start from the recipe's risk. **Raise** SAFE to CAUTION if the item changed in the last 7 days (idle known and < 7). Never lower a risk.
- **Confidence:** start from the byte source: measured 1.0, tool 0.9, estimated 0.6, unknown 0.3.
- **Overlap:** if an actionable (native or quarantine) finding's target is a strict descendant of another actionable finding's target, drop the descendant. For example, node_modules inside an old nvm version. Report how many were merged in a warning. Advise findings never absorb others.
- **ID:** `"O-" + lowercase base32(sha256(scanID + "\x00" + recipeID + "\x00" + target + "\x00" + nativeArg))[:6]`. It must be deterministic for the same scan, because `explain` recomputes it. If two IDs collide, extend both to 8 characters.
- **Title:** use the finding's title. Otherwise use the recipe title, plus ` · <base name of target>` for multi-instance recipes.
- **Explain:** `recipe.Explain`. `Note` is `finding.Note`.
- **Ranking:**
  - Tiers in the order SAFE, then CAUTION, then RISKY, then ADVISE.
  - Within a tier, sort by `Bytes.Value * Confidence` descending, then by ID.
  - `Totals` sums `Bytes.Value` for findings whose source isn't unknown.

## 2. `engine.Storage`
```go
type StorageResult struct {
    Scan        model.ScanInfo      `json:"scan"`
    Categories  []CategoryTotal     `json:"categories"`  // from opportunities: category, bytes, count, by risk
    SystemData  []SystemDataPart    `json:"system_data"` // see below
    Large       []model.Node        `json:"large,omitempty"` // only with --large
}
```
- **Categories:** group the opportunities by `Category`.
- **"System Data" decoded:** a list of parts with a name, bytes (`model.Bytes`) and an explanation. Get the snapshot count and the VM/swap volume `UsedBytes` from `probe.CollectDisk` and `probe.CollectSnapshots` via the Runner. Get purgeable bytes, and the scan's "not visible" gap (Data volume used minus scan total). Get `/private/var/folders` and `/Library/Developer/CoreSimulator` from scan nodes when present. If a value is unknown, say so; never use 0.
- **`--large`:** use `engine.Largest(nodes, 20, 1 GB)` over the latest scan, **excluding** any node equal to or under an opportunity target. These are advise-only: "no recipe, review manually".

## 3. Commands (all read-only, all with `--json` using `writeJSON`)
- **`macdoc wins [--all] [--tier safe|caution|risky|advise]`:** follow the `docs/CLI_UX.md` mockup.
  - Sections, in order: "Free & safe" (SAFE), "Worth considering" (CAUTION), "Needs care" (RISKY), and "Your call (advice only)" (ADVISE). Each shows a tier total.
  - **Grouping:** when a recipe has more than 3 opportunities and `--all` isn't set, show one line per recipe: `<n> × <recipe title> · <sum>`, followed by `(macdoc wins --all)`.
  - Each line shows the ID, size, title and a short restore note: `rebuilds on next build`, `re-downloads on demand`, or `restore.note` truncated.
  - Native items show `→ <command>` on the next line. Advise items show nothing.
  - Header: the scan age, plus warnings in a short "Notes" block at the end.
  - Footer: `macdoc explain <id> · nothing has been changed`. Don't mention `plan` yet; it arrives in Phase 5.
- **`macdoc storage [--large]`:** categories, then the System Data breakdown, then the large unknown items.
- **`macdoc dev [toolchain]`:** opportunities grouped by toolchain, with totals. With a toolchain argument, only that one; an unknown toolchain is an error that lists the valid ones.
- **`macdoc explain <O-id>`:**
  - Recompute the opportunities and find the ID; if it's missing, say `not found in the latest scan; IDs change after "macdoc scan"`.
  - Print: title, target, size and its source, risk (and why it was raised), idle days, method with the exact command (or "moved to macdoc quarantine; restorable for 7 days" for quarantine), restore cost, explain text and note.
